HIGHSCORE GAMING BOT

Van Trucker tot Developer — 12 Maanden Solo Bouwen met AI
⬇️

Het Traject

Meer dan 20 jaar geleden deed ik 2 jaar een ICT-opleiding en heb die nooit afgemaakt — maar hield er wel wat vroege programmeer- en websitebouw-ervaring aan over. Daarna werd ik vrachtwagenchauffeur. Gamen heb ik altijd al geweldig gevonden en doe ik nog steeds, en ik heb altijd gedroomd van zelf games maken — zonder jarenlange opleiding leek dat onbereikbaar, tot AI het ineens wél mogelijk maakte.

Toen ik begon wist ik helemaal niks van Flask-servers of Unity, en had ik nog nooit met GitHub gewerkt. Ik begon met ChatGPT en kopieerde code handmatig naar PythonAnywhere: één game, één leaderboard, en dagen tot weken per feature. Alles heb ik gaandeweg geleerd. Inmiddels werk ik 12 maanden met AI als co-pilot — nu via Claude Code in VS Code — en is diezelfde workflow tientallen keren sneller geworden.

Waar traditionele developers jaren over zouden doen, bewees ik dat AI development democratiseert. En dat helemaal alleen, naast een baan van 45 uur per week en een gezin met 2 kinderen. Niet door het denken over te nemen, maar door een krachtige partner te zijn in het leerproces — een partner die met mij is meegegroeid.

Het Idee

Ik zit al langer in crypto en ken wallets en blockchain goed. We hadden een eigen token met een Telegram-groep eromheen, waar we games speelden voor prijzen — via Gamee en Naka, bestaande Telegram-gameplatforms.

Onze token is een tax-token: een deel van elke transactie gaat naar een pot die de prijzen betaalt. Maar het uitkeren van die prijzen ging volledig handmatig, en dat was veel werk voor de dev van de token. Ik wilde dat altijd al automatiseren.

Leren door te Breken

De games die we al gebruikten moesten worden aangepast: TelegramParams uitlezen om de score aan de juiste gebruiker te koppelen, en die score doorsturen naar mijn server zodat de bot 'm kon tonen op het leaderboard. Dat was versie één, nog zonder blockchain — de automatische payouts (eerst Solana, later ook TON) kwamen pas daarna.

Onderweg: Unity games die geen scores doorstuurden, database connections die faalden, AI assistants die bleven dromen over verkeerde oplossingen. Elke crash was een les.

Technische Doorbraken

Flask server werkend. Blockchain payouts live. Real-time leaderboards. Async job recovery. Van frustratie naar doorbraken.

Productie-Klaar

Complete ecosystem: Unity games → Flask API → SQL Database → Telegram Bot → Blockchain. Échte users, échte tournaments, échte payouts.

Platform Expansion

Van één bot naar een compleet platform: een Telegram Mini App als frontend, meerdere Unity WebGL games, en een eigen FastAPI WebSocket-server voor real-time PvP matches.

Maand 7-9: Meer Games, Meer Diversiteit

Een aantal games gekocht op CodeCanyon (Maze Runner, Ghosty, Brick Breaker, Oldman Rush, Helix Jump, Hopper, Spaces) en herbouwd tot server-authoritative: elke game kreeg een eigen deterministische simulatie zodat de server 'm bit-identiek kan naspelen voor anti-cheat. Bij Brick Breaker verving ik ook het 3-ballen-game-over door een endless-ballen-modus, en Ghosty reskinde ik tot een nieuw personage: Buddy. Daarnaast vijf games volledig zelf ontworpen en gebouwd: Highscore Heroes, Chart Retard, HSCdash, Claudiction en Honkmaster.

Maand 9-10: Eigen Infrastructuur

Verhuizing van PythonAnywhere en Render naar een eigen Hetzner VPS. Ook de WebGL game-builds gingen van GitHub Pages — dat geen gzip goed kon serveren — naar Hetzner: kleinere downloads, snellere laadtijden in de Telegram Mini App. CI/CD via GitHub Actions, systemd services, en volledige controle over de productieomgeving.

Maand 10-11: Security Incident

Een gelekte bot-token werd binnen uren gekaapt door een externe poller. Secrets geroteerd, alles naar environment variables verplaatst, SSH gehard met fail2ban. Onder druk een productie-incident oplossen — en de infrastructuur er sterker uit laten komen.

Maand 11-12: Anti-Cheat Overhaul (lopend)

De client stuurde eerst zelf de score — makkelijk te vervalsen. Nu draait elke game op een eigen deterministische fixed-point simulatie (Q16.16, geen floats) die de server bit-identiek kan naspelen — bewezen tick voor tick gelijk tussen WebGL en Linux-native builds. Game voor game gemigreerd, dit is nog steeds het huidige hoofdwerk.

Hoe Ik Werk

Het grootste deel van het werk zit niet in de features — het zit in de opzet. Bij De Paarse Dop, een voorraadbeheer-app die ik als gunst bouwde voor een brouwerij, was ik langer bezig met de architectuur, de deploy pipeline en de database-structuur dan met de uiteindelijke site zelf.

Maar zodra die fundamenten staan — automatische deploys, duidelijke environment configuratie, een simpele git-workflow — wordt itereren triviaal. Dan kan ik features toevoegen of bugs fixen vanaf bijna elke plek, zonder de hele setup opnieuw te hoeven doordenken.

Concreet: voor elk nieuw project maak ik eerst een map aan met een VS Code workspace en Claude Code, en meteen een CLAUDE.md erin. Daarna zet ik een GitHub-flow op (die ook naar een andere plek kan pushen als dat nodig is). Bij een game komt er ook een leeg Unity-project bij, in dezelfde map of ernaast. Pas als dat allemaal staat, begin ik echt met bouwen.

Games Die Ik Solo Bouwde

Vijf games heb ik volledig zelf ontworpen en gebouwd in Unity — geen team, geen artists, geen andere developers. Alleen ik en Claude als AI-partner, van concept tot werkende WebGL-build.

Ik werk met Unity's Animator Controller voor animatie-state-machines, gebruik AI-gegenereerde 3D-modellen van Meshy waar ik custom assets nodig heb, en koop animatiepacks, levels en een sound library in de Unity Asset Store in plaats van elk wiel opnieuw uit te vinden.

Highscore Heroes

Unity WebGL PvP fighting game in een Telegram Mini App. Real-time multiplayer via WebSocket, een Budokai-stijl combo-systeem met input buffering en animatie-gestuurde windows, matchmaking, en een rule-based AI-tegenstander met vier moeilijkheidsgraden die inspringt zodra er geen menselijke tegenstander beschikbaar is. Nog lang niet af — special moves en een guard meter staan nog op de roadmap — maar al wel volledig speelbaar en live.

Chart Retard

Een satirische crypto-trading simulator: candlestick charts, procedureel gegenereerde 'shitcoins', random market events die de prijs beïnvloeden. Geld reken ik volledig in integers (nano-dollars) in plaats van floats — een precisieprobleem dat elke fintech-achtige app kent — met een seeded simulatie zodat de server elke run bit-identiek kan herspelen.

HSCdash

Een 3D endless runner met een neon-esthetiek: combo-meter, coin- en obstacle-spawners, en visuele effecten zoals light tunnels en laser fans om het tempo te laten voelen — met dezelfde deterministische fixed-point sim onder de motorkap voor server-side anti-cheat.

Claudiction

Een arcade reflex-game rond een timing-bar: precies op het juiste moment stoppen bepaalt je score. Met progressiesysteem en dezelfde seeded-replay anti-cheat als de rest van het platform.

Honkmaster

Een Paint.io-achtige multiplayer game met Telegram's bekende Utya-eendjes: spelers bewegen een eend over een canvas en kleuren territorium in, real-time via WebSocket. Van de sticker maakte ik zelf een spritesheet van 16 frames (8 richtingen × 2 zwemposes, met een berekende tilt en verschuiving voor het dobber-effect), en een eigen Python-script genereert daar automatisch 14 kleurvarianten uit.

Bots Leren Spelen

Naast de platformkant experimenteer ik met machine learning: bots trainen die mijn eigen games leren spelen, via Unity ML-Agents en eigen evolutionaire algoritmes (CMA-ES), beide getraind rechtstreeks op dezelfde deterministische game-binaries die de anti-cheat gebruikt om scores te verifiëren. De trainingen draaien als losse systemd-services op de VPS, met auto-recovery na een crash of herstart.

Het levert ook een leuke feature op voor spelers: "versla de bot" — een benchmark-run die laat zien hoe goed een getraind model een level speelt. Puur experimenteel werk, maar ik vind dit stiekem het leukste deel om aan te bouwen.

Evolutionaire Trainingsstrategie

CMA-ES en (1+λ)-ES optimaliseren actie-reeksen tegen een shaped reward, met bewezen bit-exact determinisme tussen training en replay.

Persistente Infrastructuur

Elke training draait als systemd-template, losgekoppeld van de bot-cgroup, met eigen crash-recovery en auto-restart na een server-reboot.

Problemen Oplossen in de Praktijk

The Debugging Journey

Elke developer kent dit gevoel: dagen vastzitten op een "simpel" probleem. Verouderde Solana imports die conflicteerden met Telegram libraries. Unity games die scores niet doorstuurden door verkeerde HTTP headers. AI assistants die in loops bleven hangen op verkeerde oplossingen.

De echte skill zit in het herkennen wanneer je een andere aanpak moet proberen, en de doorzettingsvermogen om door te gaan tot het werkt.
